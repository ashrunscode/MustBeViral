# 0001 Auth

Date: 2026-05-07

## Status

Accepted.

## Context

The System DNA requires signup, login, workspaces, multi-brand access, admin controls, billing, and future OAuth. The Claude audit found no implemented auth scheme, no sessions table, no OAuth table, and no password storage path. Shipping feature routes before auth would make tenant isolation and billing enforcement unreliable.

## Decision

Use custom D1-backed email/password authentication with server-side sessions and future OAuth support.

## Implementation

- `users` stores identity and role.
- `password_credentials` stores password hash, algorithm, and migration metadata.
- `sessions` stores hashed session tokens, expiry, revocation, IP/user-agent metadata, and rotation fields.
- `oauth_accounts` supports later Google/Apple/social OAuth without changing `users`.
- `invitations` supports agency/team workspaces.
- Browser sessions use secure HTTP-only cookies with SameSite Lax plus JSON/custom-header CSRF checks.
- API/service auth can add bearer tokens later without changing the user model.
- Workspace RBAC and brand RBAC are mandatory route middleware.
- Admin role is explicit and never granted at public signup.

## Password Hashing

Start with Workers-compatible WebCrypto PBKDF2-SHA-256/SHA-512 with high iteration count and per-password salt. Argon2id may replace it only after a package is verified to run in Cloudflare Workers and pass local tests.

## Consequences

- Session revocation is immediate.
- Tenant isolation can be tested against D1 state.
- OAuth remains additive.
- CSRF must be handled because browser sessions use cookies.
- Rate limiting and failed-login lockout are required before beta.
