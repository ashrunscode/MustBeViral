# W3-002 contract step: brand originals and rights

Step `w3-002-contract` of WP-PLATFORM-W3-002, the first packet of the owner's operator-first pilot
on V2. This is local evidence only. No remote database, Worker, bucket or provider was touched.

## What the migration adds

`supabase/migrations/20261008010000_platform_brand_asset_originals.sql` is additive.

**Artifact store**

- `artifacts` gains the `brand_original` kind. `project_id` may be null only for that kind
  (`artifacts_brand_original_has_no_project`). This extends the existing artifact store as
  DATA_AUTH_AND_TENANCY requires, so no second media library is created.
- `artifacts_select_member` now excludes `brand_original`. The existing Core read path
  (`getArtifact` in `apps/core/src/composition/supabase.ts`) mints preview URLs for any artifact a
  member can read. Without this narrowing it could sign an original without a rights check.
- No application or package code reads brand originals, so the narrowing removes no existing
  behavior.

**New tables**

- `asset_rights` records:
  - the basis and permitted uses;
  - recognizable-person release (a reference is required when people are released);
  - an optional expiry;
  - a one-time revocation, which cannot be undone.

  Other columns are immutable and rows cannot be deleted.

- `asset_metadata` records workspace/brand ownership, with composite keys to brands, artifacts and
  same-brand rights. It also holds the purpose, filename, content hash, measured dimensions or
  duration, and `verified_at`.
  - It is the only authority for current rights. The artifact attestation keeps `initial_rights_id`.
  - Identity and verified measurements are immutable, and rows cannot be deleted.
- Both tables:
  - enable and force RLS;
  - grant clients `select` only;
  - read through `app_private.platform_can(..., 'brand:read')`;
  - have a covering index for every foreign key.

**`public.platform_asset_command`** (authenticated)

- Operations: `create_asset_rights`, `revoke_asset_rights`, `begin_asset_upload` and
  `reassign_asset_rights`.
- Each one requires `brand:write`, takes the portfolio lock, stores an idempotency record and
  writes an audit event. A revoked actor gets no stored replay.
- A replayed `begin_asset_upload` rebuilds its current state, so a verified original never asks for
  bytes again.
- The same bytes keep one asset per brand. The same bytes under different rights or purpose fail
  with `ASSET_EXISTS` (the detail carries the existing asset ID); they are never applied silently.
- Shape errors return `VALIDATION_FAILED`: impossible dates, unknown purposes, overlong filenames,
  and control or bidi-override characters in filenames.

**`public.platform_asset_query`** (authenticated)

- Operations: `get_brand_asset`, `list_brand_assets` and `list_asset_rights`.
- Cursors are scoped to the actor and the query.

**`public.finalize_brand_asset_upload`** (service_role only)

- Core names the authenticated user who uploaded the bytes. It reports the measured hash, length,
  sniffed MIME type, and dimensions or duration.
- The function then:
  - takes the portfolio lock order;
  - rechecks that actor's current brand write authority with `platform_can_for`;
  - validates the measurements;
  - refuses any mismatch;
  - is idempotent once the original is available.
- Any current writer of the brand may complete an upload, and an actor who has lost access may not.

**Usability** is derived, never stored. An asset is usable only with verified bytes, current rights
and an active brand.

**Media limits per purpose**

| Purpose  | Types                       | Limit   |
| -------- | --------------------------- | ------- |
| Photo    | JPEG, PNG, WebP, HEIC, HEIF | 50 MiB  |
| Logo     | PNG, SVG, WebP, JPEG        | 10 MiB  |
| Document | PDF                         | 25 MiB  |
| Video    | MP4, QuickTime              | 500 MiB |

Storing HEIC/HEIF originals does not claim they can be rendered; normalization still needs proof on
real fixtures.

## Tests

`supabase/tests/database/00054_platform_brand_asset_originals.test.sql` has 91 assertions. They
cover:

- validation of rights and upload inputs, including impossible dates, duplicate uses, unknown
  purposes, and control or bidi characters in filenames;
- MIME and size limits;
- idempotent replay that reflects the current state, and a restart without a duplicate;
- conflicting reuse of a key or bytes, and `ASSET_EXISTS` for different rights or purpose;
- rights from another tenant or another brand refused;
- revoked or expired rights refused for new uploads and shown as unusable on existing assets;
- renewal by reassignment, with a stale-version guard;
- a revocation that cannot be undone, and an archived brand marked unusable and refusing uploads;
- machine verification:
  - a mismatched hash, short bytes or a sniffed MIME mismatch is refused;
  - missing or unpaired measurements and zero dimensions are refused;
  - video duration is required, documents take no dimensions, and SVG logos need no dimensions;
  - an unrelated actor and a revoked uploader are refused;
  - another current writer may complete an upload;
  - an idempotent replay is audited once;
- immutability and refusal of deletes, and direct client writes denied;
- the legacy artifact read path cannot see a brand original, while the asset query can;
- rights listing with paging, and a scoped cursor refused for another actor;
- grants and tenants:
  - a brand-scoped studio editor works on the granted brand only and cannot see an existing asset in
    the other brand;
  - a viewer cannot write;
  - a revoked grant loses reads, writes, stored replays and rights changes;
  - a revoked owner membership loses access;
  - another tenant cannot list or reach the assets.

## How the database gate was run

`pnpm supabase:test` could not run on this workstation. Docker Desktop stopped publishing container
ports: Ports are empty for every Supabase container, even with HostConfig bindings present, after a
container restart and after `docker desktop restart`. The Supabase CLI therefore cannot reach
`127.0.0.1:54322`.

The equivalent run happened inside the database container:

- one transaction that rolls back;
- `create extension pgtap`;
- this migration;
- every test file in `supabase/tests/database` in its own savepoint, with
  `supabase/tests/operator` staged so the `\ir` include in 00029 resolves.

Results are recorded in the pull request. 00004 (pooled identity reset) was not run, because it
commits by design and nothing it exercises changes here. The shared local database was confirmed
unchanged afterwards, and this migration is **not** applied to it.
