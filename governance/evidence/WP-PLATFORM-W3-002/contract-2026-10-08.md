# W3-002 contract step: brand originals and rights

Step `w3-002-contract` of WP-PLATFORM-W3-002, the first packet of the owner's operator-first pilot
on V2. Local evidence only: no remote database, Worker, bucket or provider was touched.

## What the migration adds

`supabase/migrations/20261008010000_platform_brand_asset_originals.sql` is additive:

- `artifacts` gains the `brand_original` kind. `project_id` may be null only for that kind
  (`artifacts_brand_original_has_no_project`). This extends the existing artifact store as
  DATA_AUTH_AND_TENANCY requires; no second media library is created.
- `artifacts_select_member` now excludes `brand_original`. The existing Core read path
  (`apps/core/src/composition/supabase.ts` `getArtifact`) mints preview URLs for any artifact a member
  can read; without this narrowing it could sign an original without a rights check.
- `asset_rights`: basis, permitted uses, recognizable-person release (a reference is required when
  people are released), optional expiry and a one-time revocation. Other columns are immutable and
  rows cannot be deleted.
- `asset_metadata`: workspace/brand ownership with composite keys to brands, artifacts and same-brand
  rights; purpose, filename, content hash, measured dimensions or duration and `verified_at`.
  Identity and verified measurements are immutable; rows cannot be deleted. One row per
  brand/content hash makes a restarted upload replay its intent instead of duplicating the asset.
- Both tables enable and force RLS, grant clients `select` only, and read through
  `app_private.platform_can(..., 'brand:read')`.
- `public.platform_asset_command` (authenticated): `create_asset_rights`, `revoke_asset_rights`,
  `begin_asset_upload`, `reassign_asset_rights`. Each requires `brand:write`, takes the portfolio
  lock, stores an idempotency record and writes an audit event. A revoked actor gets no stored replay.
- `public.platform_asset_query` (authenticated): `get_brand_asset`, `list_brand_assets`,
  `list_asset_rights`, with scoped cursors.
- `public.finalize_brand_asset_upload` (service_role only): Core reports the measured hash, length
  and dimensions or duration; the function rechecks the persisted initiating actor with
  `platform_can_for`, refuses mismatched or short bytes, and is idempotent once available.
- Usability is derived, never stored: verified bytes, current rights and an active brand.

Media limits per purpose: photos JPEG/PNG/WebP/HEIC/HEIF up to 50 MiB; logos PNG/SVG/WebP/JPEG up to
10 MiB; documents PDF up to 25 MiB; video MP4/QuickTime up to 500 MiB. HEIC/HEIF normalization still
needs real-fixture proof before rendering; storing originals does not claim it.

## Tests

`supabase/tests/database/00054_platform_brand_asset_originals.test.sql` (63 assertions) covers:

- validation of rights and upload inputs, MIME and size limits;
- idempotent replay, restart without a duplicate, and conflicting reuse of a key or bytes;
- rights from another tenant or another brand refused; revoked or expired rights refused for new
  uploads and shown as unusable on existing assets; renewal by reassignment with a stale-version
  guard;
- machine verification: mismatched hash, short bytes and missing measurements refused, an unrelated
  actor refused, a revoked initiating actor refused, idempotent replay audited once;
- immutability and delete refusal for metadata and rights; direct client writes denied;
- the legacy artifact read path cannot see a brand original, while the asset query can;
- a brand-scoped studio editor can work on the granted brand only; a viewer cannot write; a revoked
  grant loses reads, writes and stored replays; another tenant cannot list or reach the assets.

The test first passed 63/63 inside a single rolled-back transaction against the local database, so
the shared local schema was unchanged during development. The recorded gate runs are in the pull
request.

## Not done in this step

Core upload, verification and signing handlers; generated REST/MCP/CLI contracts; streaming bytes to
R2; frames and UI; staging migration and release. The four automated acceptance rows also require
handler tests, so they stay pending. The local Supabase database used by every worktree now has this
additive migration applied for `pnpm supabase:test`.
