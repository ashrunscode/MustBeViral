# W1 ownership mapping, specified before migration

This is implementation evidence for W1.1–W1.2, not a second product authority.

- Workspace IDs, owner memberships, projects, kits, artifacts, runs and ledger rows remain unchanged. A studio is a portfolio, never a tenant or a wallet.
- Backfill accepts explicit workspace IDs. Each must be active and have exactly one active owner membership. Missing/inactive workspaces, orphan owners and conflicting recorded mappings abort the whole transaction before any row is created. Names, email, `created_by` and portfolio visibility are not ownership evidence.
- Record one owner-to-personal-studio mapping per authenticated owner ID, and one workspace-to-default-brand mapping pinned to the exact owner membership ID. Default brand display names copy the workspace name; they do not constitute approved brand knowledge. Record each existing project-to-brand relationship explicitly. No projects or legacy kits are overwritten. Repeating the backfill preserves all IDs, and a changed owner requires a reviewed corrective mapping instead of reassignment by inference.
- New studios have an owner and explicit editor/viewer memberships. Studio ownership cannot transfer workspace ownership. Workspace owners issue grants to an exact studio and optionally an exact brand. Grants allow only `brand:read`, `brand:write`, `location:read`, `location:write`; no billing, execution, media or publishing permission is implied. Viewer membership excludes writes. Write grants require the corresponding read grant; location grants also require brand read access.
- A grant remains usable only while its issuing workspace-owner membership, studio, studio membership and workspace remain active. All child references include the workspace and brand composite keys. Archived records retain their identities and references but cannot receive new edits or grants.
- Direct authenticated table writes are denied. Hardened RPCs use the original Supabase JWT, fixed search paths, durable idempotency and database authorization. Mutations lock their studio and workspace before checking current grants; membership, grant and owner changes participate in the same serialization. Revocation committed before a waiting mutation checks authority must deny that mutation.
- Tenant actions append the existing workspace audit log. Studio-only actions use an immutable studio control-plane event table because the workspace audit contract requires a workspace; this does not duplicate a tenant ledger, execution queue or resource authority.
- Reads return only permitted rows. A resource hidden by tenant/brand scope is `NOT_FOUND`; a visible resource lacking the requested write action is `FORBIDDEN`. Pagination is bounded to 20 by default and 100 maximum, with an opaque timestamp/UUID cursor bound to the query scope. Every mutation requires idempotency; authorization is checked again before replay.
- Rollback reverts application handlers while retaining additive tables and recorded mappings. Old commands and original ledger totals must pass unchanged. No tenant rows or mapping records are deleted to simulate rollback. Local synthetic tests validate repeated mapping, missing owners, owner transfer and old-application compatibility. Staging and production migration remain separately unverified and unauthorized.

The UI successor implements saved onboarding and authenticated legacy-link resolution using these mappings. The owner-approved pilot brands are WashBodega and UnPile; local operational records are synthetic.
